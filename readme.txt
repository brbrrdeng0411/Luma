Luma — Windows 로컬 이미지 라이브러리
누적 개발 및 버전 변경 기록
현재 버전: 1.3.8
최초 개발 및 이번 기록 정리일: 2026-09-29

이 파일은 최초 개발부터 현재까지의 작업 기록입니다.
초기 개발과 첫 개선 작업을 각각 1.0.0, 1.1.0으로 정리했습니다.
앞으로 버전을 올릴 때 기존 기록을 삭제하지 않고 변경 이력을 추가합니다.

============================================================
실행과 업데이트
============================================================

실행: Luma.exe를 더블클릭합니다.
Windows 10/11 64비트용이며 필요한 Python/Qt 런타임을 포함합니다.
별도 설치, 인터넷, 계정 또는 로컬 서버가 필요하지 않습니다.
프로그램을 다른 위치로 이동할 때는 Luma 폴더 전체를 함께 옮깁니다.

기존 프로그램을 1.3.8로 업데이트하는 방법:
1. Luma를 정상 종료합니다.
2. 1.3.7에서 갱신할 때 프로그램 폴더의 app.py, Luma.exe를 교체합니다.
3. Launcher.cs 및 최신 readme.txt, 사용 안내.md, 업데이트 안내.md를 갱신합니다.
4. Luma.exe로 다시 실행합니다.

1.3.5에서 갱신할 때 runtime, viewport_image.py, libwebp.dll, libsharpyuv.dll,
icon.ico, windows_shell.py, bootstrap.py는 교체할 필요가 없습니다.
업데이트 ZIP에는 이전 버전용 공통 파일도 포함합니다. 기존 DB는 교체하지 않습니다.

중요: 이미지 폴더에 있는 .luma-library.sqlite3는 삭제하거나 교체하지
않습니다. 빈 DB를 기존 데이터 위에 덮어쓰지 않습니다. 프로그램 파일을
교체하는 위치와 사용자가 선택한 이미지 폴더는 구분해야 합니다.

1.0.0 — 최초 실행 가능한 로컬 라이브러리 완성
============================================================
작업일: 2026-09-29

요구 및 구현:
- 최상위 이미지 폴더를 선택하면 모든 일반 하위 폴더를 재귀 탐색.
- GIF/JPG/JPEG/WebP/PNG/BMP 표시, GIF 및 애니메이션 WebP 재생.
- 왼쪽은 큰 이미지 감상, 오른쪽은 태그·필터·썸네일 컨트롤.
- 좌우 방향키, 이미지 위 일반 휠, 썸네일 클릭으로 이미지 이동.
- 현재 필터 결과가 썸네일·현재 이미지·이전/다음 이동의 공통 집합.
- 여러 태그 AND 검색, 필터 변경 즉시 결과와 뷰어를 동기화.
- 새 태그 입력, 쉼표로 여러 태그 추가, 기존 태그의 + 버튼 재사용.
- 현재 이미지에서 태그 연결 제거, 이름 검색, 네 가지 정렬 지원.
- 원본은 읽기만 하며 이동·수정·태그별 복제나 디스크 썸네일 캐시 없음.
- 선택한 이미지 폴더 최상위 .luma-library.sqlite3에 자동 저장.
- 이미지 ID·상대 경로, 태그, 다대다 연결을 별도 테이블로 관리.
- 폴더 스캔과 썸네일 생성은 작업 스레드에서 처리.
- 썸네일 메모리 캐시를 384개로 제한.
- 파일 메뉴의 다시 읽기(F5), 도움말 제공.

환경 확인 및 배포:
- 실제 PC에서 Python 3.10, PyQt6 6.4.2, Pillow 설치 여부와 이미지
  디코더 지원을 확인한 뒤 구현 방식을 선택.
- .NET SDK 대신 설치된 C# 컴파일러로 작은 Windows 실행기 제작.
- Python/Qt 런타임을 포함하여 별도 개발 도구 설치 없이 실행하도록 구성.
- 실행기에서 Windows 환경 변수 Path/PATH 중복 문제를 수정.
- 실행 파일, 런타임, 소스, 사용 안내, 검증 결과와 전체 ZIP 제공.

검증 및 수정:
- 실제 Qt 키·클릭·휠 이벤트로 태그 입력·저장·재개방, AND 필터,
  썸네일 선택, 필터 결과 내 이동, 빈 결과 처리 검증.
- 태그 체크박스를 실제 체크박스 컨트롤로 수정하고 입력 흐름 검증.
- 여섯 가지 확장자, GIF/WebP 애니메이션, 손상 이미지 처리 검증.
- 원본 파일의 SHA-256 전후 일치 확인.
- 한글 경로/태그, 중복 연결 방지, 실패한 추가의 트랜잭션 롤백 검증.
- 파일이 사라졌다가 같은 경로로 돌아오면 기존 태그가 유지됨을 확인.
- 포함 런타임과 Luma.exe로 실제 창 생성 확인 및 화면 캡처 점검.

1.1.0 — 확대, 반복 태깅, 북마크, 많은 태그 탐색
============================================================
작업일: 2026-09-29

감상 개선:
- Ctrl+휠로 커서 부근 기준 확대/축소, +/− 키 지원.
- 확대 이미지를 드래그로 이동, 0 또는 더블클릭으로 화면 맞춤.
- 태그·북마크 변경 중 확대 상태 유지, 다른 이미지로 이동하면 맞춤.
- 일반 휠의 이미지 전환과 Ctrl+휠의 확대 조작을 구분.

반복 태깅 및 태그 탐색:
- Ctrl+T로 태그 찾기, 검색 후 ↓로 선택, Enter로 적용.
- 선택 태그를 유지하며 A로 추가, R로 제거, F로 필터 포함/해제.
- 입력창에서도 Ctrl+Enter로 추가, Ctrl+Backspace로 제거.
- 태그 추가·제거 저장 후 즉시 화면 갱신 및 연속 이미지 이동.
- 여러 열의 스크롤 가능한 태그 카드로 목록을 정리.
- 전체/최근 사용/자주 사용 탭, 이름 검색, 기존 네 가지 정렬 유지.
- 현재 이미지에 붙은 태그는 ✓와 색으로 구분.
- 최근/자주 사용 기록은 실제 추가·제거 작업을 기준으로 별도 저장.

북마크 및 초기 작업 위치 기억:
- Ctrl+B로 북마크 지정/해제, Ctrl+Shift+B로 검색 가능한 북마크 목록.
- 북마크가 필터 밖에 있으면 필터를 해제하고 해당 이미지로 이동.
- 북마크는 태그와 별개이며 재실행 후에도 유지.
- 마지막 폴더, 이미지, 태그 필터, 선택 태그를 기억하는 기본 복원 구현.
- 이 단계에서는 태그 정렬 상태의 저장·복원은 포함하지 않았음.

기존 데이터 보존:
- 기존 images/tags/image_tags 테이블의 행을 재생성하지 않음.
- bookmarks/tag_usage/workspace_state 테이블만 추가.
- 기존 DB 확장 전 SQLite 백업을 같은 이미지 폴더에 생성.
  파일명: .luma-library.sqlite3.before-features.bak
- 기존 이미지·태그·연결의 확장 전후 내용 일치를 검사.
- 보존 검사 실패 시 확장 트랜잭션을 롤백.
- 기존 백업을 다음 실행에서 덮어쓰지 않도록 처리.

검증:
- 기존 버전 DB의 전체 행, 백업, AND 검색 결과 보존 확인.
- 북마크 추가·제거가 태그 연결을 바꾸지 않는지 확인.
- 확대/드래그, 키보드 추가·제거·다음 이미지, 북마크 목록 이동,
  재개방 후 이미지·필터·북마크 복원을 실제 UI 입력으로 검증.
- 83개 태그에서 검색·정렬·탭·스크롤 확인.
- 기존 작업용 DB 3개의 읽기 전용 복사본으로 확장 검사.
  원본 DB 파일 해시가 변하지 않았음을 확인.
- 이전 기능 회귀 검사와 포함 런타임 실행 검사 통과.

1.2.0 — 재실행 시 작업 환경 자동 복원 완성
============================================================
작업일: 2026-09-29

변경 내용:
- 마지막 정상 사용 폴더를 자동으로 다시 여는 시작 경로를 정리.
- 다른 폴더를 정상적으로 열면 그 폴더를 마지막 사용 폴더로 갱신.
- 폴더 경로 설정을 저장한 직후 및 종료 시 명시적으로 동기화.
- 마지막 태그 정렬을 저장·복원하도록 추가:
  이름 오름차순 / 이름 내림차순 / 이미지 많은 순 / 이미지 적은 순.
- 마지막 이미지와 AND 필터를 정렬 상태와 함께 하나의 작업 상태로 저장.
- 태그 탐색 탭(전체/최근/자주)과 태그 검색어도 함께 복원.
- 복원 순서를 다음과 같이 연결:
  마지막 라이브러리 → 필터 → 정렬·태그 탐색 상태 → 현재 이미지
  → 뷰어·썸네일·태그 컨트롤 동기화.
- 복원 중 컨트롤 변경 신호에 의해 불완전한 상태가 저장되지 않도록
  신호 차단과 복원 중 저장 억제를 적용. 동기화 완료 후 한 번 저장.
- 이전 버전의 작업 상태를 그대로 읽으며, 없는 정렬 항목만 기본값으로
  보완. 이전 버전에서 저장하지 않았던 과거 정렬은 추정하지 않음.
- 잘못된 상태 값은 유효성 검사 후 안전한 기본값으로 처리.
- 기존 상태 JSON에 필드를 추가하며 알 수 없는 기존 필드는 보존.
- 이번 버전은 새 DB 테이블이나 기존 이미지·태그·북마크 스키마 변경 없음.

상태 저장 위치:
- 마지막 라이브러리 폴더 경로: Windows 사용자 앱 설정(Luma/Luma).
- 마지막 이미지·필터·정렬·탐색 상태: 기존 DB의 workspace_state 테이블.
- 기존 이미지 목록, 경로, 태그, 이미지-태그 연결, 북마크, 태그 사용
  기록은 작업 상태 저장 때문에 변경하지 않음.
- 상태 저장은 변경 시 및 정상 종료 시 수행하며 북마크와 독립적임.

예외 처리:
- 마지막 폴더가 없거나 드라이브가 연결되지 않았으면 안내를 표시.
  기억한 폴더를 삭제하거나 새 빈 라이브러리로 교체하지 않음.
  드라이브를 연결해 재실행하거나 폴더 열기로 위치를 지정할 수 있음.
- 마지막 이미지가 삭제되었거나 복원된 필터에 포함되지 않으면 해당
  필터 결과의 첫 이미지로 이동. 결과가 없으면 뷰어와 선택을 함께 비움.
- 파일의 존재 여부 재탐색은 기존 동작을 유지하며, 누락된 파일의
  태그·북마크 기록을 삭제하지 않음.

검증:
- 포함된 Python/Qt 런타임의 서로 다른 프로세스에서 실제 app.main 실행.
- 완전 종료 → 폴더 선택 없이 재실행 → 비첫번째 이미지 및 두 태그
  AND 필터 복원을 네 가지 정렬 모두에 대해 검사.
- 정렬 콤보박스, 실제 결과, 태그 체크 상태, 현재 이미지 경로,
  썸네일 모델 및 선택 이미지가 같은 상태인지 확인.
- 최근/자주 사용 탭과 검색어를 포함한 탐색 상태 복원 확인.
- 최초 실행, 라이브러리 변경, 일시적으로 사라진 폴더의 복구 검사.
- 이미지·태그·연결·북마크·태그 사용 기록의 전체 행 전후 일치 검사.
- 구버전 상태 형식 및 유효하지 않은 상태 값의 호환 검사.
- 기존 1.0/1.1 기능의 UI·저장·데이터 보존 회귀 검사.
- 테스트는 격리된 샘플 폴더와 별도 설정 파일을 사용하며 사용자의
  실제 라이브러리나 마지막 폴더 설정을 테스트 대상으로 변경하지 않음.

배포:
- 프로그램 동작 변경 파일: app.py, library.py.
- 누적 기록 파일: readme.txt 신규 생성, 최초 개발부터 이번까지 수록.
- Luma-update.zip에 위 세 파일만 포함.
- Luma-Windows.zip에는 현재 소스·런타임·문서 전체 포함.

1.3.0 — 확정된 양손 키보드 조작 체계
============================================================
작업일: 2026-09-29

확정 기본 키:
- ← / ↑: 이전 이미지. → / ↓: 다음 이미지.
- W / S: 태그 카드 위 / 아래. A / D: 태그 카드 왼쪽 / 오른쪽.
- E: 선택 태그 등록. Q: 선택 태그 연결 제거. F: 선택 태그 필터 토글.
- Ctrl+T: 태그 검색. Esc: 문자 입력을 마치고 일반 조작 상태로 복귀.

구현:
- 이전 A 등록 / R 제거 및 방향키 태그 탐색 동작을 폐기.
- 메인 화면의 방향키는 태그 목록, 입력창, 정렬 선택기, 탭, 썸네일에
  포커스가 있어도 현재 이미지 집합의 이동으로 고정.
- WASD는 실제 화면의 태그 카드 배치에 따라 공간적으로 선택을 이동.
  경계에서는 현재 항목을 유지하고, 화면 밖 항목 선택 시 자동 스크롤.
- 이미지 이동은 현재 AND 필터 결과 안에서만 수행.
- E/Q/F는 표시된 선택 태그 하나에 적용. 검색 결과가 없으면 선택을
  비워서 보이지 않는 이전 태그에 행동키가 적용되지 않도록 처리.
- 선택 카드 강조 및 선택 태그 이름, 등록됨/미등록, 필터 ON/OFF 표시.
- 등록·제거 후 이미지 태그, 태그 수, 카드 등록 표시, 결과와 뷰어 동기화.
- 입력창의 WASD/Q/E/F는 대소문자 모두 문자로 입력하고 단축키 차단.
- 입력 중 방향키 역시 사진 이동 전용이며, 텍스트 커서 위치 변경에는
  Home/End 또는 마우스를 사용할 수 있음. 일반 시스템/모달 대화상자는

현재 사용 방법 및 유지되는 동작

처음에는 폴더 열기로 이미지 최상위 폴더를 지정합니다.
다음 실행부터는 마지막 폴더·필터·정렬·현재 이미지를 자동 복원합니다.
이미지 폴더 전체를 옮겼다면 옮긴 위치를 한 번 직접 열어 주세요.

← / ↑: 이전 이미지. → / ↓: 다음 이미지. 일반 휠도 이전/다음 이미지.
Ctrl+휠 또는 +/−: 확대/축소. 드래그: 이미지 이동. 0/더블클릭: 맞춤.

Ctrl+T → 검색 → Esc → WASD 선택 → E: 기존 태그를 찾아 적용.
W/S: 위/아래 태그. A/D: 왼쪽/오른쪽 태그.
E: 선택 태그 등록/해제 토글. F: 선택 태그 필터 포함/해제.
R: 즐겨찾기 토글. Ctrl+Z: 직전 태그/즐겨찾기 편집 취소.
Ctrl+Enter: 선택 태그 등록/해제 토글. Q / Ctrl+Backspace 제거 단축키는 폐지.
Ctrl+B: 현재 이미지 북마크. Ctrl+Shift+B: 북마크 목록.
F5: 파일 추가·삭제 후 폴더 다시 읽기.

개별 이미지의 외부 이동·이름 변경을 자동 추적하지 않습니다.
같은 경로에 파일이 돌아오면 기존 태그 기록을 다시 사용합니다.
심볼릭 링크·Windows 재분석 지점은 순환 참조 방지를 위해 제외합니다.
대규모 라이브러리의 모든 장비별 성능을 보장하는 부하 검사는 수행하지
않았으며, 정상 사용자 흐름과 데이터 보존을 중심으로 검증했습니다.

소스는 GPL-3.0-or-later 조건으로 제공됩니다. 함께 제공되는 Python,
Qt, PyQt6 등은 각 구성요소의 라이선스가 적용됩니다.

1.3.2 — 이미지 원본 정렬과 파일 이름 변경·삭제
============================================================
작업일: 2026-09-29

- 썸네일 위에서 파일 이름 오름/내림, 크기 작은/큰 순, 날짜 오래된/최신
  순을 선택합니다. 날짜는 파일의 마지막 수정 시각입니다.
- 태그 AND 필터와 이미지 정렬을 함께 적용하며 감상 이동과 썸네일은
  같은 순서를 사용합니다. 정렬 변경 시 현재 이미지와 필터를 유지합니다.
- 마지막 이미지 정렬을 기존 작업 상태와 함께 저장하고 다시 복원합니다.
- 편집 → 현재 이미지 이름 변경(F2): 확장자를 유지하여 같은 폴더 안에서
  원본 이름을 바꿉니다. 이미지 ID, 태그 연결, 북마크와 현재 선택을 유지합니다.
- 편집 → 현재 이미지 파일 삭제(Delete): 확인 후 원본을 영구 삭제합니다.
  휴지통으로 보내지 않습니다. 해당 이미지의 연결·북마크만 제거하고
  태그 자체와 다른 이미지의 데이터는 유지합니다.
- 삭제 후 기존 필터·정렬 순서의 다음 이미지, 없으면 이전 이미지를
  선택합니다. 결과가 없으면 정상적인 빈 상태를 표시합니다.
- 파일 편집 중 실패에 대비해 같은 폴더의 임시 파일과 작업 기록을 사용합니다.
  실패 시 복구하며 중단된 작업은 다음 라이브러리 열기에서 복구합니다.
- 기존 workspace_state에 이미지 정렬 및 진행 중 파일 작업 정보만 추가합니다.
  기존 DB 구조나 이미지·태그·북마크를 초기화하거나 재생성하지 않습니다.
- 감상과 태깅은 원본을 변경하지 않지만, 편집 메뉴는 원본에 적용됩니다.
- 외부에서 파일 속성을 바꿨다면 F5로 다시 읽어 정렬 정보를 갱신합니다.

검증: 별도 생성한 이미지/DB로 관련 통합 검사 5개 통과.
여섯 정렬, AND 필터, 네 방향키와 썸네일 순서, 정렬·작업 상태 재실행 복원,
실제 F2 입력 및 Delete 확인창, 이름 변경 후 태그·북마크 보존,
삭제 후 다음/이전/빈 결과 전환, 관련 연결만 제거됨을 확인했습니다.
이름 충돌, DB 저장 실패, 파일 삭제 실패의 복구 및 중단 작업 재개,
대소문자 이름 변경, 재생 중 GIF의 이름 변경·삭제도 확인했습니다.
사용자의 실제 이미지 라이브러리에 시험용 이름 변경·삭제를 하지 않았습니다.

1.3.3 — 태그 관리·토글, 즐겨찾기와 직전 편집 취소
============================================================
작업일: 2026-09-29

- 편집 메뉴에서 선택 태그 이름 변경, 확인 후 태그 자체 삭제 지원.
  이름 변경은 같은 태그 ID와 모든 이미지 연결을 유지합니다. 기존 이름과
  충돌하면 덮어쓰거나 합치지 않고 안내합니다. 삭제는 그 태그의 연결과
  사용 기록만 정리하고 현재/저장 필터에서도 제거합니다.
- E 및 태그 카드 +/✓ 버튼은 등록/해제 토글로 통일했습니다.
  기존 Q 제거, Ctrl+Backspace 제거는 폐지했습니다. Ctrl+Enter도 토글입니다.
- 왼쪽 감상 영역 아래 작은 − / + / 화면 맞춤 / 100% 버튼을 배치했습니다.
  방향키와 일반 휠 이동은 유지됩니다. 100%는 원본 픽셀 크기입니다.
- R 또는 파일 이름 옆 하트로 즐겨찾기를 토글합니다. 일반 태그 및 북마크와
  독립된 favorites 테이블에 저장하며 favorite 태그를 자동 생성하지 않습니다.
- 썸네일 위 전체 사진/즐겨찾기 탭을 제공합니다. 즐겨찾기 탭에서도 기존
  태그 AND 필터, 이미지 정렬, 방향키 이동을 같은 결과 집합에 적용합니다.
  마지막 탭 상태도 복원합니다. 북마크로 이동할 때 필요하면 전체 탭으로 전환합니다.
- Ctrl+Z로 직전 태그 등록/해제 또는 즐겨찾기 등록/해제를 한 번 되돌립니다.
  다른 사진으로 이동한 뒤에도 원래 편집한 이미지에 적용합니다. 입력창의
  Ctrl+Z는 문자 편집 취소로 유지합니다. 취소 기록은 현재 실행/라이브러리에
  한정되며 원본 삭제 또는 태그 자체 삭제 후에는 비웁니다.
- 기존 DB에 즐겨찾기 테이블만 추가하고 기존 이미지·태그·연결의 보존 검사를
  수행합니다. 북마크·경로·필터·작업 상태를 초기화하지 않습니다.
- 파일 이름 변경 시 즐겨찾기도 유지하며 원본 삭제 시 해당 즐겨찾기만 정리합니다.

검증: 이번 범위의 Qt 통합 검사 4개 통과. 실제 태그 이름 변경/삭제 확인창,
E 토글과 Ctrl+Z, 새 태그 입력 취소, 필터 결과에서 빠진 이미지 복구,
R 토글·빈 즐겨찾기 결과 취소·즐겨찾기 탭 재실행 복원, 텍스트 입력 충돌 방지,
확대/축소/맞춤/100% 버튼, 기존 DB 확장 전후 행/작업 상태 동일성을 확인했습니다.
별도 생성한 시험 라이브러리를 사용했으며 사용자의 실제 라이브러리를 변경하지
않았습니다. 누적 과거 기록의 Q/E 설명은 당시 동작이며 현재 동작은 위와 같습니다.

1.3.4 — 조작과 관계없는 선택·스크롤 변경 수정 및 배포 정리
============================================================
작업일: 2026-09-29

확인한 문제와 변경:
- 태그 목록 갱신 때 선택 태그로 강제 스크롤하던 동작을 제거했습니다.
  필터 체크/해제와 사진 이동은 선택 태그와 태그 스크롤을 유지합니다.
- 태그 검색/탭에서 선택 태그가 숨겨졌다고 첫 태그를 자동 선택하지 않습니다.
  선택은 유지하고 '현재 목록 밖'으로 표시합니다. WASD/클릭으로 직접 바꿉니다.
- 최초 태그 필터 적용 직전 이미지 ID를 기억하고 마지막 필터가 해제되면
  그 사진으로 복귀합니다. 다중 필터 변경 중에는 원래 위치를 덮어쓰지 않습니다.
  이 위치도 기존 workspace_state의 position에 추가 저장하여 재실행 후 유지합니다.
  원본이 삭제됐거나 현재 즐겨찾기 탭 밖이면 현재 유효한 선택을 유지합니다.
- 동일 이미지의 태그·즐겨찾기 갱신 때 썸네일을 강제로 현재 사진까지 스크롤하지
  않습니다. 직접 이전/다음 이동과 결과 밖 이미지의 정상 전환은 유지합니다.
- 원본 이름 변경과 파일 편집 실패 시 배율·이동 위치를 유지합니다.
- 북마크 이동 시 대상에 필요한 조건만 해제합니다. 즐겨찾기 탭에 있는 대상이면
  탭을 유지하고, 태그 필터를 만족하면 그 필터를 유지합니다.

조사 범위:
태그 선택/필터/검색/정렬, 이미지 정렬, 썸네일 선택, 이전/다음, 즐겨찾기
토글/탭, 북마크, 이름 변경/삭제, 확대/축소를 확인했습니다.
정렬 후 현재 이미지 유지, 일반 즐겨찾기 토글의 현재 이미지 유지, 직접 감상
이동 시 썸네일 동기화, 삭제 후 다음/이전 선택, 확대 조작의 독립성은 유지했습니다.
상태 원칙: 사용자가 바꾼 상태와 그 결과에 필요한 상태만 갱신합니다.

용량 조사:
정리 전 배포 폴더 134,948,798바이트(134.95MB, 128.70MiB).
기존 전체 ZIP은 53,917,253바이트(53.92MB, 51.42MiB)였습니다.
약 52MB와 130MB의 차이는 현재 결과물에서 압축본/압축 해제본 차이로 확인됩니다.
초기 배포 스크립트도 같은 Python/Qt 런타임 복사 방식을 사용했습니다.
초기 ZIP 자체와의 직접 비교는 하지 않았으므로 과거 증가분 전체를 단정하지 않습니다.
Qt/PyQt 부분은 약 103.72MB입니다. ZIP 중복 경로는 없으며, 동일 내용 파일 검사에서도
용량에 의미 있는 중복은 없었습니다. 39바이트 초기화 파일과 4바이트 설치 메타데이터의
같은 내용은 각 패키지에서 필요하므로 유지했습니다.

실제 제외 항목:
- 앱이 사용하지 않고 tkinter 패키지도 배포되지 않는 Tcl/Tk DLL 2개와 _tkinter.pyd.
- CPython 내부 시험용 _ctypes_test 및 _test* 확장 모듈 7개.
- 개발 중 생성한 검증 PNG 6개, 재생성 가능한 __pycache__ 파일.
총 84파일, 4,942,468바이트를 배포 폴더에서 제외했고 작업 폴더에 보관했습니다.
Qt DLL, 렌더링 지원, 이미지 디코더와 라이선스는 그대로 유지했습니다.
정리 직후(최종 문서 갱신 전) 폴더: 130,009,484바이트(130.01MB).
사용자가 둔 icon.png와 기존 업데이트 ZIP, 바로가기는 임의로 제거하지 않았습니다.

검증:

- 실제 필터 체크 클릭 후 선택/스크롤, 검색으로 숨긴 선택 유지,
  태그/이미지 정렬 및 즐겨찾기/북마크 토글 후 관계없는 상태 유지 확인.

- 이름 변경 시 확대/이동 위치 유지, 북마크 이동의 최소 조건 변경 확인.

  태그 정렬/이미지 정렬 복원과 GIF/JPG/JPEG/PNG/BMP/WebP 읽기 통과.
- 별도 시험 DB의 이미지·태그·연결·북마크·즐겨찾기 보존 확인.
사용자의 실제 이미지 DB는 열거나 변경하지 않았습니다.

1.3.5 — 초고해상도 정지 이미지 표시 실패 수정
============================================================
작업일: 2026-10-02

원인 재현:
정상적인 12,000×12,000 RGB PNG를 생성하고 별도 이미지 검사로 정상 파일임을
확인했습니다. 기존 QImageReader.read()는 전체 크기 디코딩에서 실패했고
기존 뷰어도 빈 QPixmap을 반환했습니다. 실행 환경의 Qt 이미지 할당 제한은
128MB이며, 이 원본의 32비트 전체 표시 비트맵은 576MB입니다.
오류를 숨기거나 전역 메모리 제한을 해제하는 방식은 사용하지 않았습니다.

변경:
- 1,600만 픽셀 초과 정지 이미지만 화면용 해상도로 읽는 경로를 추가했습니다.
- 화면 맞춤/낮은 배율에서는 Qt 축소 디코딩을 사용합니다. 해당 포맷에서 지원하지
  않으면 Windows WIC 또는 WebP의 축소 디코더로 읽습니다.
- 큰 배율/100%에서는 화면에 보이는 원본 사각형만 잘라 화면에 필요한 크기로
  디코딩합니다. 확대/이동/창 크기 변경 시 해당 영역을 다시 읽습니다.
- 원본 크기와 표시용 비트맵 크기를 별도로 유지하여 맞춤과 100%를 계산합니다.
- EXIF 방향, 투명도, 이미지 전환 시 대기 중인 표시 갱신 취소를 처리합니다.
- 일반 해상도와 기존 애니메이션 재생 경로는 유지했습니다.
- 표시 실패는 실제 디코더 오류로 알리며 직전 유효한 화면을 유지합니다.
- viewport_image.py는 Windows 기본 WIC를 사용합니다. 고해상도 WebP는
  현재 환경에서 확인한 libwebp 1.3.2의 영역/축소 API를 사용합니다.
  libwebp.dll과 그 종속 libsharpyuv.dll(합계 약 447KB) 및 라이선스를 동봉합니다.
  시스템 패키지 설치나 Qt/Python 런타임 교체는 없습니다.

검증:

- 맞춤, 연속 확대/축소, 100% 원본 픽셀, 이동 후 다른 영역 재표시 확인.

  독립 실행 측정에서 프로세스 최대 작업 집합 약 51MB로 확인했습니다.

1.3.6 — 일괄 태깅 모드와 패널 크기 조절
============================================================
작업일: 2026-10-07

- 썸네일 위 '일괄 태깅 모드' 체크로 ON/OFF합니다. 기본/재실행 상태는 OFF입니다.
- ON에서는 Ctrl+클릭으로 개별 다중 선택, Shift+클릭으로 범위 선택합니다.
  선택 사진 수와 선택 범위를 표시하고 기존 태그 검색·목록·입력을 그대로 사용합니다.
- 기존 태그 +/✓ 또는 E: 모두 등록된 태그는 선택 전체에서 해제하고,
  일부/미등록 태그는 선택 전체에 추가합니다. 일부 등록은 − 표시로 구분합니다.
- 현재 태그 영역은 선택 사진의 태그 합집합을 표시하며 × 클릭으로 선택 전체에서
  해당 태그를 제거합니다. 새 태그 입력도 선택 사진 전체에 적용합니다.
- 선택이 없으면 일괄 편집을 하지 않습니다. OFF하면 현재 한 장 태깅으로 복귀합니다.
- 필터·정렬 갱신 시 이미지 ID로 선택을 유지하되 결과에서 빠진 사진은 선택에서
  제외합니다. 방향키 감상만으로 일괄 선택 범위를 임의로 바꾸지 않습니다.
- 일괄 변경은 하나의 DB 트랜잭션으로 처리하고 실패 시 전부 취소합니다.
  기존 Ctrl+Z로 직전 일괄 변경의 사진별 이전 연결 상태를 복원할 수 있습니다.
- 좌우 경계와 오른쪽 태그/썸네일 경계의 7px 핸들을 드래그해 비율을 조절합니다.
  사진·태그·썸네일 구조는 유지하며 읽을 수 있는 최소 영역은 남깁니다.
- 패널 크기는 기존 Windows 앱 설정의 panels/main, panels/right에 보관합니다.
  라이브러리 DB나 마지막 작업 상태를 초기화하거나 테이블을 추가하지 않습니다.

검증: 관련 Qt 통합 검사 4개 통과.
실제 Ctrl+클릭 선택 및 E/태그 × 전체 적용, 부분 등록 상태의 토글,
새 태그 일괄 등록·제거, OFF 후 단일 태깅, Ctrl+Z, 재개방 후 저장 유지,
필터 결과 변경 시 선택 정리, 저장 실패 시 전체 롤백을 확인했습니다.
실제 마우스 경계 드래그와 패널 복원, 동봉 런타임 두 프로세스에서
종료→재실행 후 패널 크기 복원을 확인했습니다.
시험 데이터의 다른 이미지/경로/북마크/즐겨찾기를 보존했습니다.
사용자의 실제 라이브러리는 열거나 변경하지 않고 프로그램 파일만 갱신했습니다.
